\begin{frame}[fragile]{Learning objectives}
Represent a candidate, its fitness and a population. Explain selection, crossover and mutation. Assemble a complete generational update. Interpret seeded outcomes without claiming a guarantee.\\[0.8em]
Prerequisites: Python variables, conditionals, loops and functions. Objects, comprehensions, arrays and pairing syntax are introduced here.
\end{frame}

\begin{frame}[fragile]{Model and assumptions}
\[\max_{x\in[-10,10]} f(x),\qquad f(x)=\sin x-0.2|x|.\]
This is a synthetic, dimensionless teaching model, not Planta Física measurements. The sine argument is in radians. Evaluation is deterministic; larger scores are better. The interval is a hard feasibility constraint.\\[0.7em]
Candidates and mutation draws are generated as part of learning the algorithm. No external data files are required.
\end{frame}

\begin{frame}[fragile]{1. Define the score and its reference}
NumPy evaluates the score element by element. A 400-point grid gives a sampled reference; the algorithm does not search by reading that grid.

\begin{frame}[fragile]{An analytical reference for study}
The algorithm itself uses no derivative. To audit this simple example, for $x>0$,
$f'(x)=\cos x-0.2$. On $(0,\pi)$ it changes from positive to negative at
$x^*=\arccos(0.2)\approx1.3694384$.
For $x\in[-\pi,0]$, $f(x)\le0$; for $|x|\ge\pi$,
$f(x)\le1-0.2\pi\approx0.3717<f(x^*)\approx0.7059082$.
Therefore $x^*$ is the global maximizer over the stated interval. The grid and
the genetic algorithm approximate it; neither computes this proof.
The final seed-16 point is \textbf{near} a local peak, not its exact maximizer.

\textbf{Check:} explain why rounding both fitness values to \texttt{0.706} does not make the
400-point grid and the seed-52 candidate identical.
\end{frame}

\begin{frame}[fragile]{2. Store a candidate and its score}
Construction stores a one-gene chromosome and computes its fitness. The property reads the gene; the representation prints a signed value to three decimals.

\begin{lstlisting}
class Individual:

    def __init__(self, gene_list: list[float]) -> None:
        self.gene_list = gene_list
        self.fitness = objective(gene_list[0])

    @property
    def gene(self) -> float:
        return self.gene_list[0]

    def __repr__(self) -> str:
        return f'x={self.gene:+.3f} f={self.fitness:+.3f}'
\end{lstlisting}
\end{frame}

\begin{frame}[fragile]{Why a tournament favors good candidates (1)}
With $n=10$ candidates and $k=3$ independent draws \textbf{with replacement}, rank the
candidates by distinct fitness from $r=1$ (worst) to $r=n$ (best).
All draws have rank at most $r$ with probability $(r/n)^k$. Subtract the event
that all ranks are at most $r-1$:
\[P(\text{winner has rank }r)=(r/n)^k-((r-1)/n)^k.\]
Thus the best candidate wins one slot with probability $1-0.9^3=0.271$;
its expected count over ten slots is $2.71$, not a promised count in this seed.
Tied fitness values need a tie-handling analysis; the formula assumes distinct ranks.
\end{frame}

\begin{frame}[fragile]{Why a tournament favors good candidates (2)}
Before reading the compact syntax: \texttt{[v*v for v in [2,3]]} gives \texttt{[4,9]}.
\texttt{max(["a", "long"], key=len)} returns \texttt{"long"} by comparing lengths.
The selection code applies those ideas to sampled objects and their fitness.
\end{frame}

\begin{frame}[fragile]{3. Tournament selection}
Sample three candidates with replacement and select the greatest fitness. Repeat for every output slot. The result contains references to existing objects; it does not create new genes.

\begin{lstlisting}
def select_tournament(population: list[Individual], size: int) -> list[Individual]:
    offspring = []
    for _ in range(len(population)):
        candidates = [random.choice(population) for _ in range(size)]
        offspring.append(max(candidates, key=lambda ind: ind.fitness))
    return offspring
\end{lstlisting}
\end{frame}

\begin{frame}[fragile]{Blend crossover and the two intervals}
Let parents have genes $a,b$, distance $d=|b-a|$, and $\alpha\ge0$.
Draw $u\sim U[0,1)$ and set $s=(1+2\alpha)u-\alpha$.
The two proposals are $c_1=(1-s)a+sb$ and $c_2=sa+(1-s)b$.
Each marginal proposal spans $[\min(a,b)-\alpha d,\max(a,b)+\alpha d]$.
They share one draw, so they are \textbf{complementary, not independent}:
$c_1+c_2=a+b$ before clamping. For $a=-2,b=3,\alpha=1$ the interval is $[-7,8]$.

Projection $\min(10,\max(-10,c))$ enforces the legal domain and may break the
sum identity. With identical parents, $d=0$ and this crossover cannot explore.
\texttt{pair = (2,3)} returns two values; \texttt{left,right = pair} unpacks them.
\texttt{items=[]; items.extend(pair)} makes a flat \texttt{[2,3]}, whereas \texttt{append(pair)} stores one pair.
\end{frame}

\begin{frame}[fragile]{Project a proposal into the legal interval}
A proposal above 10 becomes 10; one below -10 becomes -10. A legal value is unchanged. Projection is part of the algorithm, not a plotting adjustment.

\begin{lstlisting}
def clamp(gene: float, low: float=GENE_MIN, high: float=GENE_MAX) -> float:
    return max(low, min(high, gene))
\end{lstlisting}
\end{frame}

\begin{frame}[fragile]{4. Blend crossover}
Draw $s=(1+2\alpha)u-\alpha$, $u\sim U[0,1)$. Propose $(1-s)a+sb$ and $sa+(1-s)b$; clamp both to the legal domain. One shared draw makes the proposals complementary, not independent.

\begin{lstlisting}
def crossover_blend(gene1: float, gene2: float, alpha: float) -> tuple[float, float]:
    shift = (1 + 2 * alpha) * random.random() - alpha
    child1 = (1 - shift) * gene1 + shift * gene2
    child2 = shift * gene1 + (1 - shift) * gene2
    return (clamp(child1), clamp(child2))

def crossover(parent1: Individual, parent2: Individual) -> tuple[Individual, Individual]:
    g1, g2 = crossover_blend(parent1.gene, parent2.gene, BLEND_ALPHA)
    return (Individual([g1]), Individual([g2]))
\end{lstlisting}
\end{frame}

\begin{frame}[fragile]{Gaussian mutation, clipping, and the observed count (1)}
Draw $\varepsilon\sim N(\mu,\sigma^2)$ and propose $x'=\min(10,\max(-10,x+\varepsilon))$.
Here $\mu=0$ and $\sigma$ is a standard deviation, not a maximum jump length.
The unbounded proposal has density
\[p(y)=\frac{1}{\sigma\sqrt{2\pi}}\exp\!\left[-\frac{(y-x-\mu)^2}{2\sigma^2}\right].\]
Clipping sends out-of-domain proposals to the endpoints; the clipped distribution
is no longer an ordinary Gaussian. The script's density curve describes the
\textbf{unclipped proposal}, while the notebook histogram displays sampled, clipped values.
Both use the same sampled proposals and arrival criterion.
\end{frame}

\begin{frame}[fragile]{Gaussian mutation, clipping, and the observed count (2)}
The experiment counts $|x'-h|<1.5$ with the fixed target center $h=1.38$,
from the fixed start $x=-4.6$. The count \texttt{110/2000} is the observed fraction
\texttt{0.055}, not a probability established for every run. This is a single-jump
experiment; the full algorithm also decides whether to mutate with probability \texttt{0.1}.
\end{frame}

\begin{frame}[fragile]{5. Gaussian mutation}
Add $\varepsilon\sim N(0,\sigma^2)$ and clamp. Sigma controls typical jump size; it is not a maximum distance. In the full algorithm, mutation activates separately with probability 0.1.

\begin{lstlisting}
def mutate_gaussian(gene: float, mu: float, sigma: float) -> float:
    return clamp(gene + random.gauss(mu, sigma))

def mutate(individual: Individual) -> Individual:
    return Individual([mutate_gaussian(individual.gene, MUTATION_MU, MUTATION_SIGMA)])
\end{lstlisting}
\end{frame}

\begin{frame}[fragile]{The unbounded proposal density}
The curve is the density before clipping. Clipping adds endpoint mass. The notebook instead plots histograms of the sampled, clipped proposals; both use the same arrival criterion.

\begin{lstlisting}
def gaussian_pdf(grid: np.ndarray, mu: float, sigma: float) -> np.ndarray:
    return np.exp(-0.5 * ((grid - mu) / sigma) ** 2) / (sigma * np.sqrt(2.0 * np.pi))
\end{lstlisting}
\end{frame}

\begin{frame}[fragile]{The complete update and its invariants (1)}
The population has ten members. Each generation runs ten tournaments of size three,
then five pair decisions with crossover probability $0.8$, then ten mutation decisions
with probability $0.1$. It replaces the population as a whole. Ten generations are a
fixed computational budget, not a convergence test. The expected operation counts
are four crossed pairs and one mutated individual per generation; actual counts vary.
\end{frame}

\begin{frame}[fragile]{The complete update and its invariants (2)}
For \texttt{slots=[0,1,2,3]}, \texttt{slots[::2]} is \texttt{[0,2]}, \texttt{slots[1::2]} is \texttt{[1,3]}, and
\texttt{list(zip(slots[::2],slots[1::2]))} is \texttt{[(0,1),(2,3)]}.
An even population size is required by this pairing. Preserve population size,
gene bounds and cached fitness; a false operator decision can reuse an object,
so the operators must avoid mutating shared parent objects in place.
There is no elitism: generation-best fitness may decrease.
\end{frame}

\begin{frame}[fragile]{6. The generational update}
Initialize ten candidates; repeat select, cross adjacent pairs, mutate and replace ten times. Crossover probability is 0.8 per pair; mutation probability is 0.1 per individual. No elitism protects the previous best.

\begin{lstlisting}
random.seed(SEED)
population = [create_random() for _ in range(POPULATION_SIZE)]
history = [max(population, key=lambda i: i.fitness).fitness]
for generation in range(1, MAX_GENERATIONS + 1):
    offspring = select_tournament(population, TOURNAMENT_SIZE)
    crossed = []
    for p1, p2 in zip(offspring[::2], offspring[1::2]):
        if random.random() < CROSSOVER_PROBABILITY:
            crossed.extend(crossover(p1, p2))
        else:
            crossed.extend([p1, p2])
    population = [mutate(i) if random.random() < MUTATION_PROBABILITY else i for i in crossed]
    best = max(population, key=lambda i: i.fitness)
    history.append(best.fitness)
    print(f'Generation {generation:2d} | best {best.fitness:+.4f}')
\end{lstlisting}
\end{frame}

\begin{frame}[fragile]{Checks and interpretation}
Check population size, legal gene bounds and agreement between every gene and its cached score. Replaying a seed should reproduce the ordered population and complete history.\\[0.7em]
Counts are exact. Compare unrounded floating-point values across environments with $\mathrm{rtol}=10^{-12}$ and $\mathrm{atol}=10^{-12}$. Investigate different trajectories. Two example seeds are not an estimated success rate.
\end{frame}

\begin{frame}[fragile]{Practice: predict, modify, explain}
1. Keep parents fixed and compare $\alpha=0,0.5,1$. Which changes the proposal interval?\\[0.6em]
2. Try $\sigma=2$ from the same start. Does the arrival count establish the best setting for a whole run?\\[0.6em]
3. Run seeds 0, 1, 2 and 3. Define a success criterion before designing a larger study. Use separate experiment names; preserve the baseline.
\end{frame}

\begin{frame}[fragile]{Reasoned answers}
1. Increasing alpha expands the interval. It does not ensure better fitness; a child can move into a valley.\\[0.6em]
2. Sigma changes single-jump reach. Full-run performance also depends on selection, crossover, mutation activation and the generation budget.\\[0.6em]
3. Four runs illustrate variation. A success-rate estimate needs an explicit event, enough independent runs and uncertainty reporting.
\end{frame}

\begin{frame}[fragile]{Connection to Planta Física}
A candidate will encode physical design decisions; feasibility will reflect engineering constraints; fitness will measure a justified performance criterion.\\[0.7em]
The present one-gene score is a teaching model. Its numerical optimum is not a recommendation for a real facility. Preserve the distinction between a best observed design and a verified global optimum.

\begin{frame}[fragile]{References and counts}
Selection returns shared object references. Identity differs from equality of genes. Counter counts object identifiers; get(key, 0) handles absent individuals. Variation constructs new objects so cached fitness matches the gene.

\begin{frame}[fragile]{Pairing and replacement}
\texttt{[::2]} selects positions 0,2,...; \texttt{[1::2]} selects 1,3,... . zip pairs matching positions. extend adds individual elements; append adds one object. A conditional comprehension applies mutation or keeps the object; assignment replaces the population list.
\end{frame}
